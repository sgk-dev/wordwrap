# PRD — sgk-wordwrap: доведение до рабочего MVP

**Проект:** `/home/sgk/wordwrap` (`sgk-wordwrap`)
**Дата:** 2026-09-10
**Статус:** черновик на согласование
**Язык документа:** русский (по правилу — PRD только на русском)

---

## 1. Что это и зачем

`sgk-wordwrap` — утилита-«исправитель раскладки» для Linux, аналог Punto Switcher / xneur.
Закрывает бытовую проблему: пользователь набрал текст не в той раскладке
(`ghbdtn` вместо `привет` или `руддщ` вместо `hello`), заметил это, выделил
кусок и одной клавишей исправил — текст переписывается в правильную раскладку,
а системная раскладка переключается на соответствующую.

Инструмент **ручной**: он не следит за набором и не угадывает опечатку сам,
срабатывает только по горячей клавише на явно выделенном (или последнем набранном)
тексте.

### Целевой пользовательский результат

1. В трее (верхняя панель GNOME) есть иконка. По клику — «включить / выключить».
2. Когда включено: пользователь выделяет текст, жмёт горячую клавишу — текст
   исправляется на месте в **любом** приложении, где можно печатать: текстовый
   редактор, браузер (адресная строка и поля на странице), VS Code, Telegram
   Desktop, чат-поля, и по возможности терминал.
3. Работает в обе стороны: неважно, набирал пользователь на английской или на
   русской раскладке — конверсия и переключение раскладки происходят корректно.
4. Когда выключено — горячая клавиша ничего не делает.
5. Запускается сам при входе в систему (systemd user service / autostart).

## 3. Ограничения платформы (влияют на архитектурные решения)

Проверено командами, не предположения:

| Механизм | Статус | Следствие |
|---|---|---|
| `wtype` (посимвольная печать) | **не работает**: `Compositor does not support the virtual keyboard protocol` | Печать текста только через **буфер обмена + Ctrl+V** (uinput). Посимвольный ввод исключён. |
| `xkb-switch` | **не работает** на Wayland (краш `_M_range_check`) | Раскладка только через `gsettings`. |
| `ydotool` | демон `ydotoold` не запущен | Не используем; синтетический ввод — напрямую через `evdev.UInput`. |
| `org.gnome.Shell.Introspect.GetWindows` | **`Access denied`** (GNOME 46 закрывает не-whitelisted вызовы) | **Нельзя** узнать активное окно / app-id / заголовок. → детект «это терминал?» и blacklist по окну не реализуемы штатно. |
| `xdotool getactivewindow` | работает только для окон **Xwayland**, не для нативных Wayland | blacklist по процессу/классу окна — только частичный, ненадёжный. |
| `pyatspi` (AT-SPI) | не установлен | Детект поля пароля через доступность недоступен, пока не поставить `python3-pyatspi`. |
| `wl-copy` / `wl-paste --primary` / `wl-paste` | работают ✓ | Основной путь захвата и вставки текста. |
| `evdev.UInput` создание виртуальной клавиатуры | доступно ✓ | Путь для Ctrl+V, Ctrl+Shift+V, Ctrl+Shift+Left, Backspace. |
| `QSystemTrayIcon` | доступен ✓ | Трей делаем на PyQt6. |

**Главный вывод:** отсутствие API активного окна означает, что «умное»
поведение по приложению (терминал vs обычное поле, пропуск конкретных окон)
на этой среде невозможно. Вместо этого — **явные режимы, задаваемые
пользователем** (модификатор к хоткею для терминала) и надёжный
универсальный путь (буфер + Ctrl+V).

## 4. Пользовательские сценарии

### СЦ-1. Включение / выключение из трея
- Пользователь кликает иконку в трее → тумблер «включено ⇄ выключено».
- Иконка визуально отражает состояние (активная / приглушённая).
- В контекстном меню (правый клик): «Включено» (галка), «Настройки…», «Выход».
- Старт демона: состояние берётся из конфига (`behavior.enabled_on_start`).

### СЦ-2. Исправление выделенного текста (основной путь)
1. Пользователь выделяет мышью или клавиатурой ошибочный фрагмент.
2. Жмёт горячую клавишу.
3. Фрагмент заменяется исправленным, системная раскладка переключается на
   соответствующую исходному тексту.
4. Буфер обмена пользователя не изменяется (восстанавливается).

### СЦ-3. Исправление последнего слова без выделения (fallback, опционально)
1. Ничего не выделено.
2. Пользователь жмёт горячую клавишу.
3. Утилита выделяет последнее слово (`Ctrl+Shift+Left`), исправляет его как в СЦ-2.
- Ограничение: не во всех полях `Ctrl+Shift+Left` выделяет слово (терминал, некоторые
  веб-редакторы). Надёжный способ — всегда выделять вручную (СЦ-2).

### СЦ-4. Терминал
- Пользователь жмёт **вариант хоткея с Shift** (см. §6.1) → вставка идёт через
  `Ctrl+Shift+V` (терминалы VTE: GNOME Terminal, Tilix, console и т.п.).
- Обычный хоткей в терминале вставит `Ctrl+V` = буквальный `^V` — поэтому для
  терминала отдельный вариант.

### СЦ-5. Двунаправленность
- Набрал `ghbdtn` при активной `us` → хоткей → `привет`, раскладка → `ru`.
- Набрал `руддщ` при активной `ru` → хоткей → `hello`, раскладка → `us`.
- Правило направления: **текущая раскладка → вторая из двух**. Это корректно для
  типового случая «набрал кашу, потому что была не та раскладка» (не та раскладка
  сейчас и активна).

### СЦ-6. Автозапуск
- После `--install-service` + `systemctl --user enable --now sgk-wordwrap` демон
  стартует при входе в систему.

## 6. Технические решения по узлам

### 6.1. Горячая клавиша

**Проблема:** мы клавиатуру *слушаем*, но не *перехватываем* (`EVIOCGRAB` на
всю клавиатуру недопустим). Значит нажатие уходит и в активное приложение —
хоткей должен быть **безвредным** для приложений и **свободным** в GNOME.

**Решение — по умолчанию `Ctrl+F1`:**
- Свободен: в GNOME `Ctrl+F1` не занят (help = `Super+F1`/`Alt+F1`); в Firefox,
  Chrome, VS Code, GNOME Terminal, Telegram по умолчанию не назначен.
- Не зависит от модели клавиатуры (в отличие от `Pause`/`ScrollLock`, которые на
  TKL-Keychron K8 живут на Fn-слое).
- Пользователь сам предложил этот вариант.

**Вариант для терминала:** `Ctrl+Shift+F1` → вставка `Ctrl+Shift+V`.
(`Ctrl+Alt+F1` использовать нельзя — это переключение виртуальной консоли.)

**Тумблер включения/выключения (P2):** `Ctrl+Pause` (одиночный Pause на десктоп-
клавиатурах есть; свободен).

**Обработка «загрязнения модификаторами»:** так как хоткей содержит `Ctrl`,
перед синтетическим `Ctrl+V` нужно дождаться физического отпускания `Ctrl`
(и `Shift`). Реализация: небольшая задержка (150–250 мс, конфигурируемо) +
проверка состояния клавиш через evdev (если реалистично) перед инъекцией.

Всё конфигурируемо в `config.json` → `hotkeys.convert`, `hotkeys.convert_terminal`,
`hotkeys.toggle`.

### 6.2. Захват текста

1. `wl-paste --primary --no-newline` → если непустой после `strip()` — это наш текст.
2. Иначе, если `behavior.fallback_to_word_on_no_selection == true`:
   - uinput: `Ctrl+Shift+Left`
   - пауза `behavior.selection_settle_ms` (по умолчанию 120)
   - `wl-paste --primary --no-newline` → если непусто, это наш текст (и выделение
     сейчас активно — замена сработает).
3. Иначе — лог `sgk_no_text_acquired`, выход без действий.

**Удаляем** хрупкий путь «буфер нажатий evdev + backspace по длине слова»
(`hotkey_manager.sgk_get_last_word` / `sgk_clear_buffer` и их вызовы в
`text_processor`). Он ненадёжен и усложняет код.

### 6.3. Направление и конверсия

1. `current = layout_manager.sgk_get_current_layout()` → нормализация (`us`→`en`).
2. `target = вторая раскладка из списка` (`sgk_get_next_layout`, для 2 раскладок —
   просто другая).
3. Если нет карты `(current, target)` — лог, откат, выход.
4. `converted = mapper.sgk_convert(text, current, target)`.
5. Если `converted == text` — менять нечего, откат, выход.

Карты: `en_ru.json` даёт обе стороны (в `mapper` уже строится reverse). `en_uk.json`
на этой машине не задействован (раскладки `us,ru`), но пусть остаётся.

### 6.4. Вставка результата

Последовательность (в `SgkClipboard`, Wayland-ветка):
1. Сохранить текущий CLIPBOARD: `wl-paste --no-newline`; если команда падает /
   пусто / не-текст — пометить «нечего восстанавливать».
2. `wl-copy <converted>`.
3. Пауза `behavior.clipboard_settle_ms` (80).
4. uinput:
   - обычный режим → `Ctrl+V`
   - терминальный режим (хоткей был с Shift) → `Ctrl+Shift+V`
5. Пауза `behavior.paste_settle_ms` (80).
6. Восстановить CLIPBOARD: `wl-copy <saved>` либо `wl-copy --clear`.

Замечания:
- `wl-copy` держит фоновый процесс-владелец выделения до следующей копии — это
  нормально.
- Восстанавливается только текстовый буфер; картинка/файлы в буфере будут потеряны
  (задокументировать в README).

### 6.5. Переключение раскладки

Бэкенд только `_SgkGsettings`. Исправить/подтвердить:
- `get_current()`: `gsettings get ... current` возвращает `uint32 1` — текущий код
  делает `idx_str.isdigit()` на строке `"uint32 1"` → всегда `False` → индекс 0.
  **Фикс:** снимать префикс `uint32 ` (`raw.split()[-1]`), затем `int()`.
- `get_all()`: парсинг `[('xkb', 'us'), ('xkb', 'ru')]` через `ast.literal_eval` —
  ок, оставить.
- После конверсии: `layout_manager.sgk_switch_to(target)` →
  `gsettings set org.gnome.desktop.input-sources current <idx target>`.
- `_sgk_pick_backend`: на Wayland без рабочего gsettings — честно логировать ошибку
  и не пытаться `setxkbmap` (он на Wayland бесполезен).

### 6.6. Трей и вкл/выкл

- `QSystemTrayIcon` (PyQt6), работает через SNI (`ubuntu-appindicators`).
- Состояние «включено» = `SgkHotkeyManager` **не на паузе**. Методы
  `sgk_pause()`/`sgk_resume()`/`sgk_is_paused()` уже есть.
- Иконка: два состояния (активная / приглушённая). Нужны 2 ассета (или программная
  отрисовка через `QPainter` — проще, без файлов).
- Меню: «Включено» (checkable), «Настройки…» (P2), «Выход».
- Левый клик по иконке — тумблер.
- Старт: `enabled_on_start` из конфига → сразу `resume()` или `pause()`.
- `app.py` уже поднимает Qt в главном потоке, asyncio-цикл в отдельном — оставляем.

### 6.7. Автозапуск и окружение

- `--install-service` уже копирует `packaging/sgk-wordwrap.service` в
  `~/.config/systemd/user/` и `.desktop` в `~/.config/autostart/`.
- Проверить/дополнить unit:
  - `ExecStart` на модуль (`python -m sgk_wordwrap` через правильный интерпретатор).
  - Окружение: user-сервису обычно доступны `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`,
    `DBUS_SESSION_BUS_ADDRESS` только если сделан
    `systemctl --user import-environment WAYLAND_DISPLAY XDG_CURRENT_DESKTOP` или
    unit тянет `graphical-session.target`. Добавить в unit
    `After=graphical-session.target`, `PartOf=graphical-session.target` и в
    install.sh — `systemctl --user import-environment`.
  - Проверить, что `gsettings`/`wl-copy` из-под сервиса видят сессию.
- Группа `input` — уже есть; udev-правило `packaging/99-sgk-uinput.rules` фактически
  не требуется (доступ уже через группу), оставить как страховку, упомянуть в README.

### 6.8. Детект полей пароля (P2)

- На этой среде надёжного пути нет. Предлагается:
  - опционально `sudo apt install python3-pyatspi` → `detector` использует AT-SPI
    роль `PASSWORD_TEXT`;
  - список процессов (`keepassxc`, `pinentry*`, `1password`, …) — оставить, но
    честно пометить, что на Wayland он почти не срабатывает без данных об окне;
  - regex по заголовку окна — на Wayland не работает (нет заголовка), оставить для
    Xwayland-приложений.
- Решение о `python3-pyatspi` — за пользователем (открытый вопрос §12).

## 11. Риски и открытые технические вопросы

1. **Тайминги буфера/вставки.** Wayland `wl-copy` + немедленный `Ctrl+V` иногда
   вставляет прошлое содержимое. Митигация — конфигурируемые задержки
   (`clipboard_settle_ms`, `paste_settle_ms`), подобрать эмпирически на шаге 3.
2. **Загрязнение модификаторами.** `Ctrl` от хоткея не отпущен к моменту `Ctrl+V`.
   Митигация — задержка + проверка состояния клавиш (§6.1).
3. **Fallback «последнее слово».** `Ctrl+Shift+Left` выделяет слово не везде
   одинаково. Принимаем как P1 с ограничениями; основной путь — ручное выделение.
4. **`clipboard-indicator`** в истории буфера сохранит транзитную копию
   сконвертированного текста. Это видимый пользовательский текст, не секрет;
   но упомянуть в README. Для полей пароля критичен FR-14.
5. **Нет данных об активном окне.** «Это терминал?» решается только вручную
   (Shift-вариант хоткея). blacklist по окну/заголовку на Wayland не работает.
6. **Осмысленный текст по ошибке.** Пользователь нажал хоткей на правильном тексте →
   получит кашу. Отмена — `Ctrl+Z` в приложении (наш paste — одна операция ввода).
   Авто-эвристика направления — вне области MVP.
7. **systemd user service и окружение Wayland.** Нужен `import-environment` и/или
   привязка к `graphical-session.target`; проверить на шаге 8.
8. **Несколько интерфейсов у одной клавиатуры** (K8 виден дважды). Листенер должен
   дедуплицировать срабатывания (debounce уже есть, проверить достаточность).
